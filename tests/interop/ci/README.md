# Cross-vendor interop CI gate (issue #28)

A small, deterministic, **required** public-CI gate that exchanges typed
`Robot` samples over live DDS/RTPS between ZeroDDS and the two widely used
open-source DDS implementations — Eclipse **CycloneDDS** and eProsima
**Fast DDS** — in **both directions**. Endpoint matching *and* actual decoded
sample delivery are asserted; SPDP participant discovery alone is never a pass.

## Required matrix

| Vendor | Direction | Assertion |
|---|---|---|
| CycloneDDS | vendor writer → ZeroDDS reader | matched; samples > 0; decode errors = 0 |
| CycloneDDS | ZeroDDS writer → vendor reader | matched; samples > 0 |
| Fast DDS | vendor writer → ZeroDDS reader | matched; samples > 0; decode errors = 0 |
| Fast DDS | ZeroDDS writer → vendor reader | matched; samples > 0 |

The CycloneDDS cells also retain the issue #29 XTypes regression semantics: a
compatible final/XCDR1 case, a compatible appendable/XCDR2 case, the
final-vs-appendable XCDR2 **negative** case (which must surface a *visible*
decode error, not a silent timeout), and the `--cyclone` compatible-generation
case.

## Pieces

| File | Role |
|---|---|
| `interop_result.py` | Pure result classifier: counts → `PASS` / `EXPECTED_NEGATIVE` / `PRODUCT_FAIL` / `TIMEOUT` / `SETUP_FAIL`. |
| `run_vendor.sh` | Vendor-agnostic runner: orchestrates every cell, unique domain per cell, exact-PID cleanup, bounded timeouts, machine-readable `<vendor>-result.json` + human summary. |
| `lib.sh` | Shared exact-PID process tracking/cleanup (unit tested). |
| `install_cyclone.sh` / `install_fastdds.sh` | **Non-gating legacy dev helpers** for local reproduction. The required CI gate uses the pinned `ci-interop` image (`ci/Dockerfile.interop`), not these scripts. |
| `fastdds/` | Fast DDS `Robot` pub/sub client (`fastdds_robot`), type generated by Fast-DDS-Gen from `fastdds/robot.idl`. |
| `tests/` | Harness self-tests (classifier, cleanup) runnable on any host. |

The ZeroDDS reader/writer and the CycloneDDS Python client are reused from
`interop/cyclone-xtypes-27/` (issue #29). The per-cell domain is passed to
every client (ZeroDDS, Cyclone, Fast DDS) as an explicit CLI argument — it is
ephemeral orchestration state, not persisted ZeroDDS configuration — so each
cell runs on an isolated domain and every process logs the domain it used.

## One-command local reproduction (Linux)

Build the ZeroDDS `Robot` reader/writer once (the runner rebuilds per
extensibility as needed):

```bash
( cd interop/cyclone-xtypes-27/reader && cargo build )
```

### CycloneDDS

```bash
# Cyclone C library + Python binding (pinned):
tests/interop/ci/install_cyclone.sh
# Run both directions + the #29 XTypes cases:
tests/interop/ci/run_vendor.sh cyclone /tmp/interop-cyclone
```

### Fast DDS

```bash
# Fast DDS + Fast-DDS-Gen (pinned) and build the client:
tests/interop/ci/install_fastdds.sh
# Run both directions:
tests/interop/ci/run_vendor.sh fastdds /tmp/interop-fastdds
```

Each run writes `<vendor>-result.json` and per-cell logs to the output
directory and exits non-zero unless every cell is green (`PASS` or
`EXPECTED_NEGATIVE`).

## Harness self-tests (no DDS stack required)

```bash
python -m pytest tests/interop/ci/tests/test_interop_result.py -q
bash tests/interop/ci/tests/test_cleanup.sh
```

## Pinned versions

The required gate runs on the dedicated **`ci-interop`** image
(`ci/Dockerfile.interop`), consumed **by `sha256` digest only** — never by tag
or `latest`. The image pins the exact revisions verified on our Linux CI host:

| Component | Pin |
|---|---|
| CycloneDDS (C+Python) | `cyclonedds==11.0.1` wheel, SHA-256 `dce6350…6101` (bundles libddsc 11.0.1) |
| Fast DDS | `v3.6.1` = `4e81e8b71bcd6e7c5213c000503cba8e49d6022a` |
| Fast CDR | `v2.3.5` = `7d33a3b51a1585f5631b0a8d905bcc4f249d0f34` |
| Fast-DDS-Gen | `v4.3.0` = `cc0072b8849b35c67bd7e187990efad58e2871ae` |
| foonathan_memory_vendor | `v1.4.1` = `347cb67581e51273a612780eb256a3c134c10bae` (Fast DDS v3.6.1's `fastdds.repos` pairing) |
| Base | `ci-rust` (its `rust:1.88-bookworm` base is `sha256`-pinned) |

Git sources are pinned by full commit SHA and the CycloneDDS wheel by SHA-256;
the image is consumed by manifest digest. This is **not** bit-exact
reproducibility — the ci-rust base and apt-installed build/runtime packages
track their repositories and are not frozen. The pinned Fast DDS build — in the image and in `install_fastdds.sh` — is
configured with `cmake --compile-no-warning-as-error`: Fast DDS forces
`CMAKE_COMPILE_WARNING_AS_ERROR ON`, which the bookworm GCC 12 turns into a
false-positive `-Wmaybe-uninitialized` error in `TypeObjectUtils.cpp`; the
pinned sources are unchanged. The `install_*` scripts mirror the same canonical
versions for local reproduction but are non-gating.

## Non-goals

RTI Connext (licensed), the full pairwise vendor×vendor matrix, DDS Security,
SHM, TCP, TSN, WAN, soak and latency benchmarking. See issue #28.

## Empty ACKNACK of the vendors

Fast DDS (and, as recorded, OpenDDS and RTI Connext) send the ACKNACK of a reader that
holds nothing with `bitmapBase` 0 and `numBits` 0, which DDSI-RTPS 2.5 §8.3.5.5 makes
invalid. ZeroDDS by default drops the rest of such a datagram (§8.3.4.1 rule 6), and with
it the SEDP data that follows in it (measured on the Linux test host, sec-diag16/17: every red
zerodds->fastdds cell had rejections with `left_out` > 0, every green cell none; with the
setting all 24 cells green and no rejection). `run_vendor.sh` sets
`ZERODDS_WIRE_ACCEPT_EMPTY_ACKNACK_BASE_ZERO=1` (setting
`wire.accept_empty_acknack_base_zero`) for the ZeroDDS processes of the vendor pairs, in
one place (the block at the top). The default of ZeroDDS stays the reading of the spec.

## PL_CDR1 parameters with the rounded length

Cyclone DDS (extended header) and RTI Connext (short header) write the length of a PL_CDR1
parameter rounded up to four, the form of DDSI-RTPS 2.5 §9.4.2.11 (recorded rows;
`ast-layout` `Dialect::Cyclone` and `Dialect::Rti`, `pads_declared_length`). XTypes 1.3
§7.4.1.2.2 has the exact length, and the default reader of ZeroDDS refuses the other form.
`run_vendor.sh` sets `ZERODDS_WIRE_PL_CDR1_READING=tolerant` (setting `wire.pl_cdr1_reading`) for the cells of the Cyclone DDS and RTI vendors,
in the same place as the empty-ACKNACK setting. Fast DDS and OpenDDS write the exact
length. The default of ZeroDDS stays the reading of the spec.
