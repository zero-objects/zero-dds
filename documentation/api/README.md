# API Reference

Auto-generated API documentation per language binding. The
content here is regenerated by CI on every release tag — do not
hand-edit subdirectories.

## Browse

| Language | Path (after `make api`) | Source |
|---|---|---|
| Rust (rustdoc) | [rust/](rust/index.html) | `cargo doc --workspace --no-deps` |
| C (Doxygen on `zerodds.h`) | [c/](c/index.html) | `crates/zerodds-c-api/include/zerodds.h` |
| C++ (Doxygen on the C++ wrapper) | [cpp/](cpp/index.html) | `crates/cpp/include/` |
| C# (DocFX) | [csharp/](csharp/index.html) | `crates/cs/` |
| Java (Javadoc) | [java/](java/index.html) | `crates/java-omgdds/java/` |
| Python (Sphinx) | [python/](python/index.html) | `crates/py/` |
| TypeScript (TypeDoc) | [typescript/](typescript/index.html) | `crates/ts-wasm/`, `crates/ts-node/` |

The directories are populated by the doc-generation pipeline (see
[`gen.sh`](gen.sh)). On a fresh clone they are empty until
`make api` is run.

## Generation

Run locally:

```bash
make -C documentation api          # generate every language's API docs
make -C documentation api-rust     # only rustdoc
make -C documentation api-c        # only Doxygen for zerodds.h
```

The pipeline is split per language because each toolchain
(`cargo doc`, `doxygen`, `javadoc`, `pdoc` / `sphinx`, `typedoc`,
`docfx`) has different prerequisites — most Rust workflows already
have `cargo doc`; the others install on demand.

Toolchain prerequisites:

| Generator | Install |
|---|---|
| `cargo doc` | included with rustup |
| `doxygen` | `apt install doxygen graphviz` / `brew install doxygen graphviz` |
| `javadoc` | included with JDK |
| `sphinx` + `pdoc` | `pip install sphinx pdoc` |
| `typedoc` | `npm install -g typedoc` |
| `docfx` | `dotnet tool install -g docfx` |

The CI pipeline installs all of these via a Docker image; locally
you only need the generator for the language you care about.

## Hosting

After a release tag, static HTML is published to
`https://docs.zerodds.org/<version>/{rust,c,cpp,...}/`. The
deployment job lives in `.gitlab-ci.yml` (planned). One directory
per released version, plus `latest/` pointing at the most-recent
stable. Pre-release versions land in `next/`.

## Source-of-truth doctrine

API docstrings live with the code, not in this directory:

- Rust: `///` on every public item; CI denies `missing_docs`.
- C: Doxygen-style block comments in `zerodds.h` (cbindgen
  preserves them).
- Java: `/**`-Javadoc on every public method.
- TypeScript: TSDoc on every exported type / function.
- Python: Google-style docstrings on every public function /
  class.

The generated HTML / PDF is a derivative; the canonical reference
is the source-tree docstring.
