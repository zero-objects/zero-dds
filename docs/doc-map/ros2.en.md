# ROS 2

German original: [ros2.md](ros2.md)

This page describes the ROS 2 integration of ZeroDDS: the RMW implementation `rmw_zerodds_cpp` (crate `crates/rmw-zerodds-shim` with C layer `rmw_c/`), the mapping library `crates/ros2-rmw`, the type conversion `crates/spatial-ros2`, the diagnostic CLI `zerodds-ros2-shim`, the `ros2.*` settings of the runtime configuration, the measured interop and the known gaps. The basis is the code. Statements found only in specs, READMEs, script headers or `internal/release/OPEN-ITEMS.md` are marked "(per docs)".

## Summary

- `librmw_zerodds_cpp.so` is built against an installed ROS 2 with `crates/rmw-zerodds-shim/rmw_c/build_librmw_zerodds_cpp.sh` or the ament package `crates/rmw-zerodds-shim/ament` (`rmw_zerodds_cpp`). `packaging/linux/deb/build-rmw-deb.sh` builds it as the deb package `ros-<distro>-rmw-zerodds-cpp` (jazzy as the start value), no rpm package contains it; `packaging/docker/ros2-shim/Dockerfile` installs it from that package, the image has not been built (A18).
- Activation via `RMW_IMPLEMENTATION=rmw_zerodds_cpp`. The identifier is in `rmw_c/rmw_zerodds.c:93` and `crates/ros2-rmw/src/ffi_api.rs:51`.
- The RMW reads its settings from the same layers as every ZeroDDS program: environment, files (`--config` on the node's command line, otherwise `zerodds.yaml` and `zerodds.d/` in the system directory), `--set` above everything. The flags go outside the `--ros-args … --` blocks (`ros2_config::process_source`, `crates/rmw-zerodds-shim/src/ros2_config.rs`).
- All measurements come from ROS 2 Humble (RoboStack environment on the Linux test host). For Iron and Jazzy a CI job is defined that is not included in any pipeline.
- Services run with `rmw_cyclonedds_cpp` and `rmw_fastrtps_cpp` in both directions, each in the correlation form of the peer. Measured on the Linux test host (ROS 2 Jazzy, `std_srvs/SetBool`, server and client in two processes, five pairs with ZeroDDS on at least one side, five runs of ten calls each): 250 of 250 replies. Before, with a ZeroDDS server the first call was lost at times (ZeroDDS client 2 of 3 runs, Fast DDS client 2 of 5); two causes in `zerodds-rtps`, both fixed: a reader proxy that joined behind the cache stayed "behind" for the writer for good, so every later SEDP announcement waited for the next HEARTBEAT (100 ms), and DATA from a writer that wrote before this side's match was requested only after that writer's next HEARTBEAT (Fast DDS: 3 s).

## Quick start

Prerequisites: Linux (the script uses `cc -shared` and `.so`), ROS 2 with dev headers (`/opt/ros/<distro>` or a RoboStack environment), Rust toolchain.

```bash
# 1) Rust bridge (librmw_zerodds.so) + C API (libzerodds.so)
cargo build -p rmw-zerodds-shim -p zerodds-c-api --release

# 2) C layer with the unprefixed rmw_* ABI (librmw_zerodds_cpp.so)
ROS_PREFIX=/opt/ros/humble ZERODDS_TARGET=$PWD/target/release \
  bash crates/rmw-zerodds-shim/rmw_c/build_librmw_zerodds_cpp.sh

# 3) register, as the test runners do
cp crates/rmw-zerodds-shim/rmw_c/librmw_zerodds_cpp.so /opt/ros/humble/lib/
cp target/release/librmw_zerodds.so target/release/libzerodds.so /opt/ros/humble/lib/
mkdir -p /opt/ros/humble/share/ament_index/resource_index/rmw_implementation
touch /opt/ros/humble/share/ament_index/resource_index/rmw_implementation/rmw_zerodds_cpp

# 4) use
export RMW_IMPLEMENTATION=rmw_zerodds_cpp
ros2 run demo_nodes_cpp talker

# 5) check
cargo run -p rmw-zerodds-shim --bin zerodds-ros2-shim -- doctor
```

Optional: a `ros2` drop-in at `/etc/zerodds/zerodds.d/50-ros2.yaml`. The template is in `packaging/linux/configs/ros2.yaml.example`.

## Building against an installed ROS 2

`build_librmw_zerodds_cpp.sh` (57 lines):

- Required environment: `ROS_PREFIX` (install prefix), `ZERODDS_TARGET` (Cargo release directory with `librmw_zerodds.so` and `libzerodds.so`). Optional `OUT`.
- Include paths with `-idirafter` for each `$ROS_PREFIX/include/*/`. According to the comment in the script, Cyclone's `dds/features.h` otherwise shadows the glibc file `<features.h>`.
- Links `-lrmw_zerodds -lzerodds -lrmw -lrmw_dds_common -lrcutils -lrosidl_typesupport_introspection_c -lrosidl_runtime_c -lstdc++`, sets rpath to `ZERODDS_TARGET` and `$ROS_PREFIX/lib`.
- Registers nothing. At the end it prints the commands for registration (copy to `$ROS_PREFIX/lib`, marker `share/ament_index/resource_index/rmw_implementation/rmw_zerodds_cpp`).

Cargo features of `rmw-zerodds-shim` (`Cargo.toml`):

| Feature | Default | Effect |
|---|---|---|
| `flatdata-loan` | yes | loan path for `delivery.mode: raw-same-host` (SHM) |
| `delivery-iceoryx` | no | loan path via iceoryx2 for `delivery.mode: iceoryx` |
| `security` | no | `rmw_zerodds_init` builds a DDS Security participant from `security.enclave_dir` |

The test runners build without `security`. `run_loaned_message_test.sh` and `run_qos_translation_test.sh` add `delivery-iceoryx` when `ZERODDS_TEST_ICEORYX=1`.

Distributions:

- Measured: Humble. Documented are `rmw_cyclonedds_cpp` 1.3.4 (`docs/ros-column.md`, `src/ros2_config.rs`) and `rmw_fastrtps` 6.2.7 (`src/services.rs`).
- Iron and Jazzy: `ci/jobs/rmw-distro-build.yml` defines `rmw-humble`, `rmw-iron` and `rmw-jazzy`. The file is not referenced by any `include:` in `.gitlab-ci.yml` or `ci/*.yml` (`git grep rmw-distro`). A run is therefore not documented.
- `zerodds-ros2-shim doctor` rates `ROS_DISTRO` in `humble|iron|jazzy|rolling` as `ok`, all others as `warn` (`src/bin/zerodds-ros2-shim.rs:554`).

ament path (`ament/CMakeLists.txt`, README section "In a ROS-2 workspace"): the package `rmw_zerodds_cpp` builds the C layer against the ROS packages, installs `librmw_zerodds_cpp` together with `librmw_zerodds.<ext>` and `libzerodds.<ext>` from `$ZERODDS_HOME/target/release` into `lib/` and registers the implementation in the ament index (`CMakeLists.txt:1-12`, `135-139`); checked by `rmw_c/run_ament_package_test.sh`.

## Selection and initialisation

- `rmw_get_implementation_identifier` returns `rmw_zerodds_cpp`.
- `rmw_init` takes `options->domain_id` and sets `RMW_DEFAULT_DOMAIN_ID` to 0 (`rmw_zerodds.c`, `rmw_init`). It then calls `rmw_zerodds_init(domain)`.
- `rmw_zerodds_init` (`src/lib.rs:706`) runs as follows:
  1. `ros2_config::process_source()` reads `--config`/`--set` from the command line of the process (outside the `--ros-args … --` blocks) and through them loads environment, files and `--set` (`ConfigSource::for_program`, stem `zerodds`), then `Ros2Config::from_config`. On an error it reports `rmw_zerodds_init: invalid configuration: …` on stderr, returns NULL, and `rmw_init` fails.
  2. With feature `security` and `security.enclave_dir` set, the participant is created from the same `ConfigSource` via `security_ffi::runtime_create_secure_ros_from_source`. A set but faulty enclave yields NULL; a silent fallback is not provided.
  3. Otherwise it is created via `runtime_create_ros_from_source` (`crates/zerodds-c-api/src/lib.rs`): the reader offers XCDR1 and XCDR2.
  4. It creates the writer and reader for `ros_discovery_info` (NoKey, RELIABLE, TRANSIENT_LOCAL, KEEP_LAST(1)).

System directory (`crates/config/src/layers.rs:406-434`): `/etc/zerodds` on Linux, `/usr/local/etc/zerodds` on macOS, `%PROGRAMDATA%\ZeroDDS` on Windows. Linux additionally reads `/run/zerodds/zerodds.d`. Missing files count as defaults.

## Settings from the runtime configuration

Reader: `crates/rmw-zerodds-shim/src/ros2_config.rs` (`KEYS`, `Ros2Config::from_config`) for `ros2.*` except `time_based_filter`. `ros2.time_based_filter`, `delivery.mode` and `security.enclave_dir` are read by `RuntimeConfig` in `crates/dcps/src/runtime.rs`. `--set` works in the RMW as in the diagnostic CLI; `--check-config` on the command line of a node has no effect, the report is produced by `zerodds-ros2-shim --check-config` with the same flags.

| Setting | Values | Env | Effect | Source |
|---|---|---|---|---|
| `ros2.topic_mangling` | `rmw` (default) \| `none` \| `custom` | – | `rmw`: `rt/<name>`, services `rq/<name>Request` and `rr/<name>Reply`; `none`: name without leading `/`; `custom`: prefix + name | `Ros2Config::dds_topic`, `dds_service_topics` |
| `ros2.custom_mangling.topic_prefix` | string | – | required with `custom`; rejected without `custom` | `from_config` |
| `ros2.custom_mangling.request_prefix` / `response_prefix` | string, default `rq/` / `rr/` | – | service prefixes with `custom` | `from_config` |
| `ros2.qos_profiles.<name>` | fields `reliability`, `durability`, `history`, `depth`, `deadline_ms`, `lifespan_ms`, `liveliness`, `liveliness_lease_ms` | – | replaces fields of a standard profile (`sensor_data`, `services`, `parameters`, `parameter_events`, `default`) or creates a new one | `standard_profiles`, `read_patch` |
| `ros2.topic_overrides[]` | `ros_topic` + exactly one of `qos_profile` or `qos` | – | replaces the named fields of the QoS that the application requests; applies to publishers, subscriptions and services | `effective_qos`, calls `src/lib.rs:1362`, `:1940`, `src/services.rs:396` |
| `ros2.time_based_filter` | list of `SECONDS` or `/topic=SECONDS`; `0` switches off | `ZERODDS_TIME_BASED_FILTER` (comma list) | `minimum_separation` per subscription; a topic entry takes precedence over the default | `runtime.rs:1527-1564`, `time_based_filter_for` (`:4724`), test `runtime_config_layering.rs::delivery_mode_and_time_based_filter_are_typed_settings` |
| `delivery.mode` | `portable` (default) \| `raw-same-host` \| `iceoryx` | `ZERODDS_DELIVERY_MODE` | loan path of the C layer via `rmw_zerodds_delivery_mode` | `runtime.rs:1493-1511`, `src/lib.rs:1810` |
| `security.enclave_dir` | directory | `ZERODDS_SECURITY_DIR` | SROS2 enclave, only with feature `security` | `crates/zerodds-c-api/src/security_ffi.rs:354` |
| other runtime settings (`discovery.*`, `transport.*` …) | see [config.en.md](config.en.md) | – | also apply to the RMW | `ffi_runtime_config` |

Rejected with a reason (`OWNED_ELSEWHERE`): `ros2.namespace` (rcl, `--ros-args -r __ns:=`), `ros2.ros_domain_id` (`ROS_DOMAIN_ID`), `ros2.enclave` (→ `security.enclave_dir`), `logging` (rcutils), `discovery.multicast` (→ `discovery.no_multicast`) and `discovery.unicast_initial_peers` (→ `discovery.peers`). Unknown keys in `ros2` and in the profile and override maps also lead to an abort (`Section::only`). Other ZeroDDS programs skip `ros2.*` (`is_rmw_path`, `runtime.rs:4083`).

`avoid_ros_namespace_conventions` uses the ROS name including the leading `/`, without prefix. For services only `Request`/`Reply` is appended.

Example (excerpt from `packaging/linux/configs/ros2.yaml.example`, reader test `the_shipped_example_reads_as_it_says`):

```yaml
ros2:
  topic_mangling: rmw
  qos_profiles:
    sensor_data:
      depth: 5
  topic_overrides:
    - ros_topic: /scan
      qos_profile: sensor_data
    - ros_topic: /map
      qos:
        durability: transient_local
        history: keep_last
        depth: 1
  time_based_filter:
    - 0.1
    - /scan=0.5
```

The `time_based_filter` lines come from the test in `runtime_config_layering.rs`. The template shows the form `time_based_filter: "/scan=0.1"` only commented out. Whether the file form is read as a string is not checked.

## What the RMW implements

From `rmw_zerodds.c`, `src/lib.rs` and `src/services.rs`:

- **Pub/sub:** `rmw_publish`, `rmw_take`, `rmw_take_with_info`, serialised variants (introspection CDR, C and C++ type support), `rmw_serialize`/`rmw_deserialize` and `rmw_get_serialized_message_size`. DDS type name per ROS convention (`std_msgs::msg::dds_::Int32_`), NoKey endpoints.
- **Wait:** `rmw_wait` waits on a condvar of the context that the reader listener signals (comment in `src/lib.rs`). Guard conditions and `rmw_*_set_on_new_*_callback` are implemented.
- **QoS:** All fields of `rmw_qos_profile_t` go to the endpoint (`src/qos.rs`, `qos::resolve`). `rmw_*_get_actual_qos` returns the applied state. `rmw_publisher_assert_liveliness` and `rmw_publisher_wait_for_all_acked` are implemented. `rmw_qos_profile_check_compatible` runs via `rmw_dds_common` (`rmw_zerodds_qos.cpp`).
- **Services/clients:** topics `rq/<svc>Request` and `rr/<svc>Reply`, types `<pkg>::srv::dds_::<Srv>_Request_`/`_Response_`. Two correlation forms (`src/services.rs`):
  - Cyclone form: `u64 guid` and `i64 seq` before the body, `clientid=`/`serviceid=` in USER_DATA. The server waits up to 100 ms for the reply reader.
  - Related identity form: inline QoS PID 0x800f (Fast DDS) and additionally 0x0083 (DDS-RPC). ZeroDDS also uses this form between ZeroDDS instances.
  - The server replies in the form of the request. The client selects the Cyclone form only when all matched servers are Cyclone DDS.
  - `rmw_service_server_is_available` is implemented.
- **Graph:** `rmw_get_topic_names_and_types` (with `no_demangle`), `rmw_get_service_names_and_types`, `rmw_count_publishers/subscribers/services/clients`, the four `rmw_get_*_names_and_types_by_node`, `rmw_get_publishers_info_by_topic`/`rmw_get_subscriptions_info_by_topic`, `rmw_get_node_names` and `rmw_get_node_names_with_enclaves` via `ros_discovery_info`.
- **Loaned messages:** `rmw_borrow/publish/take_loaned_message`, `can_loan_messages` only for fixed-size types (`zerodds_msg_can_loan`). Delivery modes `portable`, `raw-same-host` (POSIX SHM, no wire) and `iceoryx` (feature `delivery-iceoryx`). Without the feature, `rmw_zerodds_publisher_enable_iceoryx` returns `RMW_RET_UNSUPPORTED`; according to the comment in `src/lib.rs:2379` the caller stays on `portable`.
- **REP extensions** in `rmw_zerodds_ros2_ext.h`: REP-2007 type adaptation (`rmw_zerodds_publish_adapted`/`take_adapted`, also request and response), REP-2008 loan memory (`rmw_zerodds_*_get_loan_memory`, `ZERODDS_LOAN_ALIGNMENT`, kernel levels 2 and 3), REP-2009 type hash (`rmw_zerodds_compute_type_hash`, RIHS SHA-256).
- **Security:** only with feature `security`, the source is `security.enclave_dir`. Expected files (`crates/security-runtime/src/profile.rs:583`): `cert.pem`, `key.pem`, `identity_ca.cert.pem`, `permissions_ca.cert.pem`, `governance.p7s`, `permissions.p7s`. rcl passes its security options (`security_root_path` from `ROS_SECURITY_KEYSTORE` and the enclave, `enforce_security` from `ROS_SECURITY_STRATEGY=Enforce`) to `rmw_zerodds_init_with_security`: the path is then the enclave directory; `Enforce` without an enclave and a build without `security` with ROS security are errors; `security.enclave_dir` and an rcl enclave at the same time are rejected (`docs/specs/zerodds-ros2-bridge-1.0.md` §7.1). Measured (`run_ros2_security_test.sh`, the Linux test host Humble): secured zerodds talker to secured zerodds listener 12 messages, to an unsecured one 0, to a secured `rmw_cyclonedds_cpp` 13.

QoS events, content filter, message info (`rmw_zerodds.c`):

- **QoS events:** `rmw_publisher_event_init`/`rmw_subscription_event_init` for OFFERED/REQUESTED_DEADLINE_MISSED, LIVELINESS_LOST/CHANGED, OFFERED/REQUESTED_QOS_INCOMPATIBLE, MESSAGE_LOST and, where the distribution has them (`__has_include`), PUBLICATION/SUBSCRIPTION_MATCHED and *_INCOMPATIBLE_TYPE. The state lives in the runtime (`zerodds_writer_get_status`/`zerodds_reader_get_status`); an event is ready when its counter has moved since the last `rmw_take_event`, and `rmw_take_event` reports the change. The status hook of the runtime (`DcpsRuntime::add_status_hook`) wakes `rmw_wait`. `rmw_event_set_callback` via one dispatcher thread per context (`src/events.rs`). Measured (Linux test host, Humble, `test_rmw_qos_events.py`): deadline on both sides, incompatible QoS (RELIABILITY) on both sides. LIVELINESS_CHANGED counts transitions like the DCPS `DataReader`, not the number of writers currently alive.
- **Content filter:** `rmw_subscription_set/get_content_filter` and `content_filter_options` at creation; expression per DDS 1.4 Annex B (`zerodds-sql-filter`), fields by name from the introspection members (`a.b` nested); applies to `rmw_take`, the raw modes, loan, serialised and adapted (REP-2007) takes; announced in the SEDP subscription. Test: `run_content_filter_test.sh` (rclcpp; rclpy in Humble has no content filter).
- **Message info:** `publisher_gid` is the writer GUID (also `rmw_get_gid_for_publisher`), `source_timestamp` the INFO_TS timestamp, `publication_sequence_number` the RTPS sequence number; samples without this information (same runtime, durability replay) report 0 or `RMW_MESSAGE_INFO_SEQUENCE_NUMBER_UNSUPPORTED`. `rmw_feature_supported` reports both sequence numbers.
- **Other:** `rmw_take_sequence` takes up to `count` messages; `rmw_get_gid_for_client` returns the GUID of the request writer; `rmw_publisher/subscription_get_network_flow_endpoints` the unicast locators announced via SEDP (UDP/TCP, IPv4/IPv6; not reachable via rclpy in Humble, not measured).
- **Not implemented:** `rmw_init/fini_publisher_allocation`, `rmw_init/fini_subscription_allocation` return `RMW_RET_UNSUPPORTED` (like `rmw_fastrtps_cpp`); `rmw_set_log_severity` has no effect.

## Diagnostic CLI `zerodds-ros2-shim`

Binary `zerodds-ros2-shim` (`crates/rmw-zerodds-shim/src/bin/zerodds-ros2-shim.rs`, `VERSION = "1.0.0"`). cargo-dist alias `zddsros2` (`Cargo.toml:498`). `zerodds-ros2` is the name of the deb package that contains this binary; there is no binary `zerodds-ros2`. The CLI is not a daemon. It reads the same layers as the RMW (`ConfigSource::for_program(…, "zerodds", ros2_config::is_key, …)`).

| Subcommand | Function |
|---|---|
| `info` | version, `rmw_implementation`, `ROS_DISTRO`, domain, mangling, number of profiles and overrides, multicast, peers, enclave |
| `topics` | configured `topic_overrides` |
| `topic <ROS_TOPIC>` | DDS topic name under the active mangling |
| `qos <PROFILE>` | profile from `ros2.qos_profiles` (`default`, `sensor_data`, `services`, `parameters`, `parameter_events`, `configured`) |
| `enclaves` | `security.enclave_dir` |
| `validate <FILE>` | check FILE as runtime base with `FILE.d/` |
| `selftest` | mangling and QoS lookup round trip, reads no configuration |
| `catalog` | JSON catalogue |
| `metrics` | catalogue of the Prometheus metric names; the RMW counts none of them (per docs, `docs/spec-coverage/zerodds-ros2-bridge-1.0.open.md`) |
| `doctor` | checks `RMW_IMPLEMENTATION`, `ROS_DISTRO`, `ROS_DOMAIN_ID`, discovery (multicast or peers), security and mangling; exit 5 on `fail` |
| `graph` | local participant and configured topics; no discovered remote endpoints (comment above `cmd_graph`) |

| Option | Meaning |
|---|---|
| `--config FILE` / `--config=FILE` | different runtime base with `FILE.d/`; a node makes the same choice with `--config` on its command line |
| `--set PATH=VALUE` | one setting above all files, repeatable |
| `--check-config` | check files and the `ros2` section, print every value with its origin |
| `--domain ID` | domain instead of `ROS_DOMAIN_ID`; only as a separate argument, `--domain=ID` ends with `unknown argument` |
| `--version`, `-V`; `--help`, `-h` | version or help |
| `--runtime-config`, `--log-level`, `--enclave` | rejected, with a pointer to the replacement (`REFUSED_FLAGS`) |

Exit codes: 0 on success, 1 on invocation or configuration errors, 5 for `doctor` with at least one `fail`. Tests: `crates/rmw-zerodds-shim/tests/shim_cli_e2e.rs` (16 `#[test]`).

Distribution: deb package `zerodds-ros2` with `/usr/bin/zerodds-ros2-shim`, `/usr/share/zerodds/configs/ros2.yaml.example`, `man 1 zerodds-ros2-shim` and `man 5 zerodds-ros2.yaml` (`packaging/linux/deb/assemble-debs.sh:152-163`). Also in the Docker image `packaging/docker/ros2-shim/Dockerfile` (default command `doctor`) and in `packaging/docker/cli/Dockerfile`. There is no systemd unit and no launchd plist (`tools/traceability/tests/deployment_layout.rs::the_ros2_diagnostics_cli_is_not_installed_as_a_service`).

RMW package: `ros-<distro>-rmw-zerodds-cpp` (`packaging/linux/deb/build-rmw-deb.sh`, `--distro`, jazzy as the default) installs into `/opt/ros/<distro>`: `lib/librmw_zerodds_cpp.so`, the two libraries it resolves by DT_NEEDED and RPATH `$ORIGIN`, `lib/librmw_zerodds.so` and `lib/libzerodds.so`, `include/rmw_zerodds_cpp/*.h`, the ament index entries under `share/ament_index/resource_index/{packages,rmw_typesupport}/rmw_zerodds_cpp` and `share/rmw_zerodds_cpp/package.xml` with the CMake files. The file list is produced by `cmake --install` of the ament project alone (as for `zerodds-dev` in `assemble-debs.sh`); there are no maintainer scripts, because it is a library and not a daemon. The supported distros are `humble jazzy kilted rolling`; the weekly job `ci/full.yml::ros-rmw-deb` runs as a matrix, once per distro (images `ros:humble-ros-base-jammy`, `ros:jazzy-ros-base-noble`, `ros:kilted-ros-base-noble`, `ros:rolling-ros-base`), checks the .deb's file list, installs it with `dpkg -i`, lets rcl load it through `RMW_IMPLEMENTATION`, and then exchanges `std_msgs/String` "0"…"19" between two processes with `packaging/linux/deb/rmw-pubsub-check.py`. After that `packaging/linux/deb/rmw-type-hash-check.py` checks the type hash (`typehash=RIHS01_…;` in USER_DATA) a peer process reads, against the package itself and both ways against `rmw_fastrtps_cpp` (not on Humble, which has no type hashes), and on Rolling `packaging/linux/deb/rmw-service-info-check.py` checks the servers and clients of a service.

## Known gaps

From `internal/release/OPEN-ITEMS.md` and the code:

- No rpm package carries `librmw_zerodds_cpp.so`; the deb package `ros-<distro>-rmw-zerodds-cpp` and the image that installs it exist but have not been run: the weekly job `ci/full.yml::ros-rmw-deb` has never run, the image has not been built (A18).
- SROS2 is missing from the default build (feature `security`).
- No documented run for Iron, Jazzy and Rolling; macOS and Windows are not covered by the build script.
- Prometheus counters and OTLP spans in the rmw path are missing (per docs).
- Per the crate's `README.md`: readiness in the raw modes is a prefetch per wait wakeup. Hooking the cross-process futex into the `rmw_wait` condvar via a c-api notify getter is open (`docs/specs/zerodds-delivery-modes-1.0.md` §11).
