## §7.2.5 Other Characters Recognized by IDL (Punctuation)

**Status:** `partial` — the operator ladder and `#` are covered one by one; no test covers all 28 characters of Table 7-7 or all five of Table 7-8. The iso-8859-1 letters of Table 7-2 are not probed either.

## §7.2.6.2.2 Escape Sequences

**Status:** `partial` — the decimal and hexadecimal forms are covered in the lexer test, the `\u`/`\U` form only as an `.idl` fixture under `tools/idlc/tests/idl-4.2-gaps/`, not as a Rust test.

## §7.4.1.3 Syntax (Productions 1–68)

**Status:** `partial` — the productions are recognised, but production 62 allows `native_type` as a member type spec too (`<type_spec> ::+ <native_type> | …`); `struct S { native H; };` is not covered, `parse_type_spec` has no `Native` branch. The gap is measured in [`idl-4.2.gaps.md`](idl-4.2.gaps.md) §A.

## §7.4.1.4.4.2.2 Floating-Point Types

**Status:** `open` — `float` and `double` are modelled and tested. `long double` the tree models as `Float128`, but Rust stable has no `f128`; the arithmetic of a `long double` expression is therefore refused (`EvalError::LongDouble`), and the clause demands the full IEEE double-extended value with at least 15 exponent and 64 significand bits.

## §7.4.1.4.4.6 Native Types

**Status:** `partial` — the declaration is covered, the use as a member type (`struct S { native H; };`) is not; see the item on §7.4.1.3.

## §7.4.3.4.3.2.1 Inheritance Rules

**Status:** `open` — there is neither a diagnostic for a base interface named twice nor a transitive walk in the front end; the check `inheritance_rules` in `crates/idl-lower/src/validate.rs` applies only to `TypeKind::Structure`. The keyword `virtual` occurs nowhere in today's tree. The flattening in `crates/lang-rules` happens per column, not in the front end.

## §7.4.3.4.3.3.1 Operations

**Status:** `partial` — `oneway` and `raises` are tested. For the directions `in`/`out`/`inout` and for the `context (…)` clause there is no test that goes through the front end: the `context` clause is parsed and lowered (`OperationNode::contexts`), but no committed `.idl` file of the tree contains one, and `ParamDirection` is checked only in hand-built model tests.

## §7.4.3.4.3.3.2 Attributes

**Status:** `partial` — `readonly attribute` and the derivation of the operations are covered; `getraises` and `setraises` are parsed and lowered (`add_attribute_raises`), but no test asserts anything about them. Only the fixture `crates/idl-parse/tests/fixtures/spec_features/attr_raises.idl` drives them through the pipeline, without a statement about the result.

## §7.4.4.4 Multiple Inheritance and Ambiguity

**Status:** `partial` — the flattening over a diamond and the ambiguity report on the model level are covered. A front-end diagnostic for the ambiguity from two inherited, *differently* declared elements does not exist: `inheritance_rules` in `crates/idl-lower/src/validate.rs` knows only `TypeKind::Structure` as an inheritance carrier.

## §7.4.4.4 Attribute and Operation with the Same Name

**Status:** `open` — `one_namespace_per_scope` gathers attribute and operation names into *one* name list, but no test lets an attribute and an operation of the same name arise in an interface. The obvious counter-check is missing.

## §7.4.5.4.1.3.2 Initializers

## §7.4.6.4.1.3 Repository Id Conflict

## §7.4.6.4.4 Use of Native Types

## §7.4.7.4.3 Value Inheritance Rules

## §7.4.7.4.4 Custom Marshaling

**Status:** `partial` — `truncatable` is recorded as a modifier and evaluated in Table A.8. The truncation itself is not carried as such in `crates/corba-codegen/src/skeleton.rs` and has no test.

## §7.4.7.4.6 Value Base

**Status:** `partial` — in the model `ValueBase` is present and reachable in every position; no language backend emits a form for it. The probe `bb7-132-valuebase` stands in `expected.tsv` for Rust *and* C on `err` (`NoLanguageForm { construct: "ValueBase" }`).

## §7.4.8.4.2.1 Facets and §7.4.8.4.2.2 Receptacles

## §7.4.9.4.1 Home Header

## §7.4.10.4.4.2 Object Root

## §7.4.11.4.1.1 Port Type Declaration

**Status:** `partial` — present in the model and tested as `InterfaceKind::PortType`; `Service::is_remote` excludes `PortType` from every DDS-RPC binding. ## §7.4.11.4.3 Connectors

**Status:** `partial` — `connector` is present in the model as `InterfaceKind::Connector`; the `port`/`mirrorport` members are parsed and lowered, but the CCM rewrite deliberately discards them (`crates/ccm/src/transform.rs`, line 255 ff., with the comment that the mapping through the port type is not §6 of this specification). ## §7.4.13.4.1 Void Content

**Status:** `partial` — the empty struct is accepted and the model carries it; the C backend refuses it (`NoLanguageForm`, C23 §6.7.2.1p8 leaves a structure without a named member undefined). Rust emits it.

## §7.4.13.4.3.3 Duplicate @position

**Status:** `open` — `check_bitmask_bounds` checks `@bit_bound`, the number of values and the range of `@position`, but not that two `@position` values are equal. `bitmask B { @position(1) A, @position(1) C };` is accepted; the later value overwrites the earlier in the model.

## §7.4.13.4.6 Ranges for all Integer Types (Table 7-26)

**Status:** `partial` — the table `primitive_range` mirrors exactly the columns of Table 7-26, but it is read only for case labels of a discriminator. The value range of a *constant* is not checked: `value_disagrees_with` compares only the form of the literal value, not its numeric value; `const octet K = 300;` and `const int8 K = 200;` go through.

## §7.4.14.3 Rule (216) — template_type_spec as type_spec

**Status:** `open` — the clause is not checked as its own form. The path it would open (`struct S { sequence<long> m; };`) is not reachable in today's parser: `parse_member` demands a `Declarator`, and `sequence<long> m;` is read as a declarator. The test `a_sequence_member_carries_its_element_type` checks the template module form, not the anonymous one.

## §7.4.14.3 Rule (217) — array_declarator as declarator

**Status:** `partial` — the array dimensions are recognised at the declarator and assigned to it; that is tested through the `typedef` path. The anonymous form `struct S { long arr[3]; };` has no test of its own.

## §7.4.14.4 Nested Templates and `>>`
