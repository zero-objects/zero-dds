## 2.1 Implementation: IDL -> C# source per Chapter 7

**Status:** `partial` — the walk transforms IDL into C# source but follows Chapter 7 only in the type core; the API shape deviates in the points itemised below (fields instead of properties, `T[]` instead of `ISequence<T>`, no `I` prefixes, no `System.Exception` base).

## 7.1.1 Two naming schemes, selected via @csharp_mapping

**Status:** `open` — the materialiser knows no `@csharp_mapping` and no switch; it follows one fixed rule (type names verbatim, members with the first letter raised).

## 7.1.1 Collision resolution: `@` prefix for keywords, `_` prefix for spec names

**Status:** `partial` — the `@` prefix for C# keywords is implemented; the `_` case for spec-introduced names (`Constants`) is missing because the materialiser does not treat them as reserved (`ZdConstants`).

## 7.1.1.1 IDL naming scheme: names without case transformation

**Status:** `open` — the scheme is not selectable. The materialiser transforms members (first letter raised) and leaves type names verbatim, a mixture matching neither scheme.

## 7.1.1.2 .NET Framework Design Guidelines naming scheme

**Status:** `partial` — members are only raised in the first letter, types and enumerators stay verbatim; the .NET rules (full Pascal Case, `I` prefix) are not applied.

## 7.1.1.2.1 Pascal Case transformation

**Status:** `partial` — only the first letter is raised (`my_field` -> `My_field`); underscores are not removed because a full Pascal Case is not injective over the names IDL 4.2 §7.2.3 permits (the reason is in the module doc).

## 7.1.1.2.2 Camel Case transformation

**Status:** `partial` — operation parameters are taken verbatim, not transformed into Camel Case.

## 7.1.2 Reserved names (C# keywords + `Constants`)

**Status:** `partial` — the C# keywords are tracked as reserved; the name `Constants` is not, because the class is called `ZdConstants`.

## 7.2.3 Constants: two alternatives

**Status:** `partial` — only the container variant exists, and it is not selectable via `@csharp_mapping`; the standalone variant is missing.

## 7.2.3.1 Standalone constants: one class per constant with `Value`

**Status:** `open` — constants are held as `const` fields in a shared `ZdConstants` class, not as one class per constant.

## 7.2.3.2 Constants container: `public static partial class Constants`

**Status:** `partial` — the class is `public static`, but neither `partial` nor named `Constants`, and not configurable via the annotation.

## 7.2.4.1.2 Floating-point types (Tab.7.3)

**Status:** `partial` — `float` and `double` match; `long double` is emitted as the generated sixteen-octet holder `global::ZeroDds.Idl.Float128`, not as `decimal` (the spec itself warns about precision loss; the deviation is justified in the module doc).

## 7.2.4.2.1 IDL sequence -> Omg.Types.ISequence<T>

**Status:** `partial` — sequences are emitted as `T[]`; the runtime declares `ISequence<T>`/`IBoundedSequence<T>`, but the materialiser does not reference it.

## 7.2.4.2.1 Tab.7.4: sequences of basic types

**Status:** `partial` — the element types match, the container type is `T[]` instead of `Omg.Types.ISequence<T>`.

## 7.2.4.2.1 Sequence/map members as read-only properties (with @external)

**Status:** `partial` — members are public, writable fields, not properties; `@external` does not change the C# form.

## 7.2.4.2.3 IDL wstring -> C# string (UTF-16)

**Status:** `partial` — no test checks that IDL `wstring` maps to C# `string`; the cited corpus run only checks that the cases render.

## 7.2.4.2.4 IDL fixed -> C# decimal + ArithmeticException

**Status:** `partial` — `fixed<P,S>` is held as a `string` carrying the decimal; the spec demands `decimal`. Reason: `decimal` has 28-29 digits, IDL 4.2 permits up to 31 (evidenced in the module doc).

## 7.2.4.3.1 IDL struct -> C# public class

**Status:** `partial` — a `public sealed class` with one public field per member is produced; properties, the copy/all-values constructors and `IEquatable<T>` are missing, and initialisation is C# default initialisation.

## 7.2.4.3.2 IDL union -> C# public class (discriminator protocol)

**Status:** `partial` — the class carries `_d` and one field per case; the `Discriminator` property, getter pairs, `Set<Member>` modifiers, `InvalidOperationException` and `IEquatable<T>` are missing.

## 7.2.4.3.3 @bit_bound underlying type for enums

**Status:** `partial` — `: int` is always written; `@bit_bound` selects no underlying type.

## 7.2.4.4 IDL array -> C# array + bounds check

**Status:** `partial` — arrays are emitted as jagged `T[][]` fields; there is no setter with a length check (fields instead of properties).

## 7.3 IDL any -> Omg.Types.Any

**Status:** `partial` — the runtime declares `Omg.Types.Any`, but the materialiser refuses `any` by name (`MaterialiseError::NoLanguageForm`) instead of mapping to it.

## 7.4 IDL interface -> C# public interface

**Status:** `partial` — methods and attribute properties as well as `in`/`out`/`ref` match; the `I` prefix is missing (name verbatim), and derived interfaces are flattened into the single declaration instead of inheriting through a base list.

## 7.4.1 IDL exception -> C# class : System.Exception

**Status:** `partial` — the class exists with one field per member but deliberately does not derive from `System.Exception` (reason: CS0108/ CS0542 for members like `message`; evidenced in the module doc).

## 7.4.2 Interface forward declaration

**Status:** `partial` — the quoted test checks that a forward declaration without a definition is refused as E002; none checks that one with a definition produces no declaration of its own.

## 7.5 I<Name>Operations + I<Name> + <Name> class

**Status:** `partial` — exactly one interface declaration is produced; the §7.5 Operations/container split and the embedded types in a `<Name>` class are missing.

## 7.6 IDL valuetype -> abstract class + factory attribute

**Status:** `partial` — a `sealed class` with the state members is produced; the abstract class, the public/private -> protected split, operations and the `FactoryAttribute` are missing.

## 7.14.1 Struct with single inheritance -> C# extends

**Status:** `partial` — the base members are folded into the derived `sealed class` (XTypes 1.3 layout), but there is no C# base class (`extends`).

## 7.14.3.1 IDL map -> IDictionary<TKey,TValue>

**Status:** `partial` — maps are emitted as `ZdEntry_<k>_<v>[]` (an array of a generated two-field class), not as `IDictionary`. The reason is the order axis (`MapEntryOrder`), evidenced in the module doc.

## 7.14.3.2 IDL bitset -> C# struct + IEquatable

**Status:** `partial` — a class with one public field per bitfield (correct holder width) is produced, not a `struct` with properties and `IEquatable<T>`.

## 7.14.3.3 IDL bitmask -> C# enum `[Flags]` + BitArray

**Status:** `partial` — a `[Flags]` enum with the correct holder and position values is in place; the `Flags` suffix on the name and the `BitArray` use are missing.

## 7.16.1 Defining annotations -> attribute class

**Status:** `open` — the materialiser refuses annotation types (`TypeKind::AnnotationType`); no attribute class is produced.

## 7.16.2 Applying annotations

**Status:** `open` — user annotations are not propagated; the only emitted annotation is the internal `[IdlName]`.

## 7.16.2.1 Annotations on typedefs propagate

**Status:** `open` — there is no attribute propagation, neither through typedefs nor otherwise.

## 7.17.1 @id, @autoid (no impact)

**Status:** `partial` — no test compares the C# form with and without `@id`/`@autoid`; the cited corpus run only checks that the cases render.

## 7.17.1 @optional -> Nullable<T> + OptionalAttribute

**Status:** `partial` — value types become `T?`, reference types stay unchanged; the `Omg.Types.OptionalAttribute` is not emitted.

## 7.17.1 @extensibility, @final, @mutable, @appendable (no impact)

**Status:** `partial` — no test compares the C# form of the `@extensibility` variants; the cited corpus run only checks that the cases render.

## 7.17.2 @key -> KeyAttribute

**Status:** `open` — the materialiser does not evaluate `@key` and emits no `[Key]`; `Omg.Types.KeyAttribute` sits unused in the runtime.

## 7.17.2 @must_understand (no impact)

**Status:** `partial` — no test compares the C# form with and without `@must_understand`; the cited corpus run only checks that the case renders.

## 7.17.2 @default_literal

**Status:** `open` — `@default_literal` is not evaluated; the C# enum default remains the value 0.

## 7.17.3 Units and ranges: @default, @range, @min, @max, @unit

**Status:** `open` — neither default initialisation nor range checks nor `UnitAttribute` are implemented.

## 7.17.4 @external

**Status:** `open` — `@external` does not change the C# form; there is neither an `ExternalAttribute` nor `IEnumerable<T>` for external sequences.

## 7.17.4 @nested (no impact)

**Status:** `partial` — no test compares the C# form with and without `@nested`; the cited corpus run only checks that the case renders.
