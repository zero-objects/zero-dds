Open: of Level 1 the TSS evaluation of an authorization token (X.509 attribute certificates per the IETF AC profile, trusted privilege authorities, access identity against the client or asserted identity) and `privilege_authorities` in the IOR; Level 2 (Proxy Info extension, forward trust evaluation, `DelegationByClient` and the IOR flags of Table 10.17); stateful conformance (§10.6.4): only the stateless mode is built, no TSS retains and no CSS establishes reusable contexts (`MessageInContext`, §10.3.2.2); without a `client_authentication_token` no TSS derives the client authentication identity from the transport layer (§10.3.1.1, Table 10.3 row P2A/None/P1): `authenticate_gssup_with`, `authenticate_with_verifier` and with them `CorbaServer` require a GSSUP token and refuse an identity assertion with a TLS client certificate and an empty token as invalid evidence, `corba-iiop` does not pass on the client certificate of an SSLIOP connection; the daemons `zerodds-corba-bridged` and `zerodds-naming-svc` have no configuration key for trust rules — they call `authenticate_gssup` with `AssertionTrust::new()`, so a user can assert only itself and the anonymous identity there; the proof against JacORB 3.9 (identity assertion with `ITTPrincipalName` in both directions) is not written and not run.
