## 1.1 Mapping IDL v4 -> Java

**Status:** `open` — no generator maps IDL to the Java forms of clause 7. The Java column produces a wire binding whose own documentation names the departures from this spec.

## 2.1 Implementation: IDL -> Java source per §7

**Status:** `open` — the Java column transforms IDL into Java source, but by the XCDR2 binding's PSM, not by clause 7.

## 7.1.1.0 Naming schemes: IDL vs. Java; selected via @java_mapping

**Status:** `open` — `@java_mapping` does not exist in the tree (`git grep java_mapping` finds nothing), and there is no switchable naming-scheme selection.

## 7.1.1.0 Name collision with reserved names: underscore prefix

**Status:** `partial` — Java keywords are escaped, but with a **trailing** `_` (`class_`) instead of the prescribed leading one (`_class`). The reserved-name list of §7.1.2 is also incomplete (see there).

## 7.1.1.1 IDL Naming Scheme: names without case transformation

**Status:** `open` — the Java column does keep IDL names unchanged (`a_module_is_a_nested_class_and_two_modules_do_not_collide`), but it is not a naming scheme and identity with the IDL naming scheme is neither intended nor tested.

## 7.1.1.2 Java Naming Scheme: JavaBeans 1.01 conventions

**Status:** `open` — getX/setX accessors and the JavaBeans conventions are not generated.

## 7.1.1.2.1 Pascal Case Transformation Rules

**Status:** `open` — no Pascal-case transformation for type and member names.

## 7.1.1.2.2 Camel Case Transformation Rules

**Status:** `open` — the only camel-case conversion in the tree is `Java::camel` in `crates/lang-rules/src/emit/java.rs` for wire method names; member names are not transformed.

## 7.1.1.2.3 All Uppercase Transformation Rules

**Status:** `open` — constants keep their IDL spelling; no uppercase transformation.

## 7.1.1.2.4 All Lowercase Transformation Rules

**Status:** `open` — module names are not lowercased; a module `a` becomes the nested class `a`, a module `common` the class `common`, but without the spec transformation.

## 7.1.1.3 Suffixes (e.g. Abstract); underscore prefix on collision

**Status:** `open` — no reserved-suffix handling; there is no `Abstract`-suffix mapping (the valuetype mapping is absent anyway).

## 7.1.2 Reserved Names

**Status:** `partial` — Java keywords plus `true`/`false`/`null` are listed. `<type>Abstract`, `Constants` and the `java.lang.Object` methods are missing.

## 7.1.3 Holder<E> class for inout/out parameters

**Status:** `open` — there is no class `org.omg.type.Holder<E>`; the former runtime class `crates/idl-java/runtime/rpc/Holder.java` was removed with `b7589e6b904`. The RPC binding carries out/inout in an `_Out` type named by DDS-RPC (`crates/lang-rules/src/emit/interface_java.rs`).

## 7.2.2 IDL module -> Java package

**Status:** `partial` — modules are mapped to **nested classes** in one file, not to packages (the crate justifies this with the one-public-type- per-file rule). Two same-named types in different modules therefore do not collide, but the spec form (package name) is not reached.

## 7.2.3 Default mapping: IDL constant -> public final class with a value field

**Status:** `open` — an IDL constant becomes a `public static final` **field** in the enclosing scope, not a same-named wrapper class with `value`.

## 7.2.3.1 Alternative mapping: Constants container class

**Status:** `open` — no `Constants` container and no `constants_container` parameter.

## 7.2.4.1.1 Integer Types Mapping (Tab.7.2)

**Status:** `partial` — `int8 -> byte`, `short -> short`, `long -> int` and `long long -> long` match. The unsigned types depart deliberately: `uint8`/`octet -> int` (spec: `byte`), `unsigned short -> int` (spec: `short`), `unsigned long -> long` (spec: `int`), because the column wants to hold the full value range.

## 7.2.4.1.2 Floating-Point Mapping (Tab.7.3)

**Status:** `partial` — `float -> float` and `double -> double` match. `long double` becomes `org.zerodds.wire.Float128`, not `BigDecimal`.

## 7.2.4.1.5 IDL boolean + TRUE/FALSE -> Java boolean + true/false

**Status:** `partial` — `boolean` becomes `boolean` (test above); no test checks that the constants `TRUE`/`FALSE` become `true`/`false`.

## 7.2.4.1.6 IDL octet -> Java byte

**Status:** `partial` — `octet` becomes `int`, not `byte`; the column justifies this with the range 0..255, which a signed `byte` cannot hold.

## 7.2.4.2.1.1 Sequences of basic types -> type-specific interfaces

**Status:** `open` — no `BooleanSeq`/`CharSeq`/… interfaces; a sequence becomes a Java array.

## 7.2.4.2.1.1 Bounds checking on bounded sequences

**Status:** `open` — there is no bounded-sequence type. A Java array throws `IndexOutOfBoundsException` natively, but the spec form (bounded sequence interfaces) is absent.

## 7.2.4.2.1.2 Sequences of non-basic types -> java.util.List<E>

**Status:** `open` — a sequence becomes a Java array `T[]`, not `java.util.List<E>`.

## 7.2.4.2.2 IDL string -> java.lang.String + IndexOutOfBoundsException

**Status:** `partial` — `string` becomes `java.lang.String` (evidenced in the test as an element type). The range checking is missing; the bound is not enforced.

## 7.2.4.2.3 IDL wstring -> java.lang.String

**Status:** `partial` — `wstring` and `string` share `java.lang.String` (UTF-16). The range checking is missing.

## 7.2.4.2.4 IDL fixed -> java.math.BigDecimal + ArithmeticException

**Status:** `partial` — `fixed<P,S>` becomes `java.math.BigDecimal` (CORBA 3.3 part 3 §1.5.6); the codec writes and reads the decimal digits through `Writer.writeFixed` and `Reader.readFixed`. The range check throws `WireException.OutOfRange`, not `java.lang.ArithmeticException`; that is the remainder. Log: `.agent/REPORT.md`.

## 7.2.4.3.1 IDL struct -> Java public class + Serializable + bean accessors + constructors

**Status:** `partial` — a nested class with `public` fields is produced. Missing: `implements java.io.Serializable`, accessors/modifiers, the all-values constructor and the public default constructor.

## 7.2.4.3.1 Default constructor: initialise members

**Status:** `open` — there is no public default constructor with this initialisation. `default_java.rs` provides a `zd_def_<T>()` defaulter for the decoder (DDS-XTypes Table 9), not the spec constructor.

## 7.2.4.3.1 Accessor/modifier naming per naming scheme

**Status:** `open` — no accessors are generated.

## 7.2.4.3.2 IDL union -> Java public final class + discriminator accessor

**Status:** `partial` — the union becomes a class with an `_d` field and one `public` field per case. Accessors/modifiers, the `getDiscriminator()` access and the `__default()` forms are missing.

## 7.2.4.3.3 IDL enum -> Java public enum + valueOf(int)

**Status:** `partial` — the enumeration becomes a class with one instance per enumerator, the constants `public static final int _NAME`, `value()` and `from_int(int)` (CORBA 3.3 part 3 §1.5.9); a member is an instance of the class. A Java `enum` and the `valueOf(int)` of the spec are missing: the class carries the value an `enum` would not have for values the reader's IDL does not know. Log: `.agent/REPORT.md`.

## 7.2.4.3.4 Constructed recursive types

**Status:** `partial` — Java reference semantics carry recursive types, and the corpus contains them; a test that names the recursion is missing (the one cited runs only with `--include-ignored`).

## 7.2.4.6 IDL typedef -> no Java type; use replaced; annotations propagate

**Status:** `partial` — the `typedef` declares nothing and its use takes the target type (test). The propagation of annotations to the uses is missing.

## 7.3 IDL any -> org.omg.type.Any

**Status:** `open` — `any` has no Java form in this column and is refused by name, not mapped to an `Any` type.

## 7.4 IDL interface -> Java public interface

**Status:** `partial` — `@service` interfaces become `public interface` with methods and attribute accessors; but the binding follows DDS-RPC 1.0 §7.11.2 (no `throws`, out/inout in `_Out` types). The base path for non-service interfaces is missing.

## 7.4.1 IDL exception -> Java class extends RuntimeException

**Status:** `partial` — the exception becomes a nested data class (in struct form). It explicitly does **not** extend `RuntimeException`; the crate justifies this with `serialVersionUID`.

## 7.4.2 Interface forward declaration: no Java mapping

## 7.5 Embedded type/const/exception decls in the interface body
