## 2.1 Implementation: IDL -> C++ source per Chapter 7

**Status:** `partial` — the data-type transformation is live and renders every corpus case (or names its refusal); the compiler gate checks the generated headers. Chapter 7 is not fully met: the `omg::types` runtime (type traits, `Any`, `fixed`, `sequence`/`string` aliases) is missing, §7.4 interfaces run through the DDS-RPC binding rather than the generic form, and §7.4.1 exceptions and §7.6 valuetypes are shaped differently.

## 7.1.2 Reserved Names

**Status:** `partial` — collisions with C++ keywords are detected and rewritten, but with a **trailing** underscore (`class` -> `class_`), not with the **leading** underscore §7.1.2 mandates (`_class`). Detection is complete; the applied mapping deviates.

## 7.1.4 IDL Type Traits (Tab.7.1 and Tab.7.4-7.12)

**Status:** `open` — no `omg::types` namespace. `grep -rl "omg::types" crates/ tools/ runtime/ endpoints/` finds only `crates/corba-codegen/src/traits.rs` (a Rust CORBA generator). The C++ column writes `std::` types directly; no trait of Tables 7.1 and 7.4-7.12 is emitted.

## 7.2.3 Constants

**Status:** `partial` — numeric and boolean constants are emitted as `inline constexpr`. String, wstring and fixed constants are emitted as `const char *`, not as `constexpr omg::types::string_view` or `std::string_view`; the `L` prefix for wide literals is missing because `wstring` is held as UTF-8. No assertion covers the constant form directly.

## 7.2.4.1 Basic Types (Tab.7.2/7.3)

**Status:** `partial` — `long -> std::int32_t` is asserted (array, interface and verbatim tests), and `octet`/`uint8` as well as `wchar`/ `unsigned short` collapse onto one type (tag test). The remaining table widths (`short -> int16_t`, `long long -> int64_t`, `char`, `wchar`, `boolean`, `octet`, `float`) have no assertion of their own. `long double` is deliberately mapped to `zerodds::wire::Float128` instead of the platform-dependent C++ `long double` (§7.2.4.1.2). `cpp_primitive` is exhaustive, so a missing primitive is a compile error.

## 7.2.4.2.1 omg::types::sequence/bounded_sequence

**Status:** `open` — neither `omg::types::sequence<T>` nor `omg::types::bounded_sequence<T,N>` nor the `is_bounded`/`bound` specialisations exist.

## 7.2.4.2.2 Strings -> std::string

**Status:** `partial` — `string` is held as `std::string` (an allowed form). There is no direct assertion for the data member (only the tag test shows that `string` and `wstring` fall onto the same C++ type); `omg::types::string` is missing.

## 7.2.4.2.2 omg::types::string/bounded_string

**Status:** `open` — no `omg::types::string`/`bounded_string<N>` aliases, no `is_bounded`/`bound` traits.

## 7.2.4.2.3 Wstrings

**Status:** `partial` — `wstring` is held as `std::string` with UTF-8, not as `std::wstring` and not as `omg::types::wstring`; the spec form is not met. No direct assertion.

## 7.2.4.2.3 omg::types::wstring/bounded_wstring

**Status:** `open` — no `omg::types::wstring`/`bounded_wstring<N>`, no traits.

## 7.2.4.2.4 Fixed Type

**Status:** `open` — the data-type column maps `fixed<P,S>` to `std::string` in `crates/lang-rules/src/adapter/cpp.rs`. The hand-written `dds::core::Fixed<P,S>` in `crates/cpp/include/dds/core/Fixed.hpp` is the DDS-PSM-Cxx runtime (a different spec) and offers only BCD round-trip plus string conversion, not the ~30 spec methods; `omg::types::fixed` and the `digits`/`scale` traits are missing.

## 7.2.4.3.2 Unions

**Status:** `partial` — the union is emitted as a class with a `_d` field and one field per branch (asserted: `struct U {`, `std::int32_t _d;`). The required accessor/modifier methods, the multi-label variant and `_default()` are missing; the branches are public fields.

## 7.2.4.3.3 Enumeration Type Traits

**Status:** `open` — the `bit_bound`/`underlying_type` specialisations are not emitted (see §7.1.4).

## 7.2.4.3.4 Constructed Recursive Types

**Status:** `partial` — forward declarations for aggregates and `std::vector<T>`/`std::shared_ptr<T>` allow self-reference; only the `@external` recursion case is evidenced (`std::shared_ptr<::m::Node> next;`). The general case (self-reference through `sequence<Node>` without `@external`) has no assertion of its own.

## 7.2.4.4 omg::types::array and dimensions

**Status:** `open` — `omg::types::array` and the `dimensions` trait are missing.

## 7.2.4.6 Naming Data Types

**Status:** `partial` — `typedef` is emitted as a `cpp::Alias` (C++ `using`); no assertion checks the alias declaration directly, and the corpus compile does not distinguish an alias form from a macro form.

## 7.3 Any -> omg::types::Any

**Status:** `open` — `any` is refused in `crates/lang-rules/src/adapter/cpp.rs` (`cpp_value_type`, `TypeKind::Any`) with `NoLanguageForm` (test `an_any_member_is_refused_by_name_at_any_depth`, also for `sequence<any>`). No `omg::types::Any`.

## 7.4 Interfaces -> C++ classes

**Status:** `partial` — interfaces are emitted through the DDS-RPC 1.0 §7.11.1 binding as classes with pure-virtual operations and attribute accessors (asserted: `in` by value/const ref, `out`/`inout` by reference, accessor named after the attribute). The binding follows DDS-RPC 1.0 and adds `IAsync`/`Requester`/`Replier`/`Client`/`Service`, which §7.4 does not know; `omg::types::ref_type<T>`/`weak_ref_type<T>` for interface parameters are missing.

## 7.4.1 Exceptions

**Status:** `partial` — an IDL exception is emitted as a `struct` with its members. The required `class X : public std::exception` derivation, `what()`, copy/move constructor, assignment operators and the explicit `(member..., const char* what)` constructor are entirely missing.

## 7.4.2 Interface Forward Declaration

**Status:** `open` — interface forward declarations are not emitted; the data-type adapter writes `Forward` only for `Structure`, `Union` and `Valuetype`. `interface Foo;` without a definition is refused by `crates/lang-rules/src/adapter/interface.rs` as `ForwardWithoutDefinition` (test `crates/lang-rules/tests/interface_bindings.rs::a_forward_declaration_without_a_definition_is_e002`).

## 7.5 Embedded declarations and static constexpr

**Status:** `open` — the DDS-RPC binding in `crates/lang-rules/src/emit/interface_cpp.rs` emits topic types and operation classes, but no nested type/exception/constant declarations inside the interface body and no `static constexpr` inside the class.

## 7.6 Valuetype -> abstract class

**Status:** `partial` — `valuetype` is treated like a `struct`: its members become fields. The required public/protected pure-virtual accessor/modifier methods, the `<ValueTypeName>_factory` class, the public-virtual inheritance and the operations of a supported interface are missing.

## 7.14.1 Structures with Single Inheritance

**Status:** `partial` — base members are copied flat into the derived struct (`all_members_of`), not as `struct Child : Base` with public inheritance; the `swap` function for inherited members is missing. The flat form is deliberate so the member order matches the wire plan.

## 7.14.2 Union Discriminators

**Status:** `partial` — the discriminator runs through `cpp_value_type` and accepts any integral type; only `switch (long)` is asserted. `wchar`, `octet`, `int8` and `uint8` as discriminators have no assertion of their own.

## 7.14.3.1 Map Type Traits

**Status:** `open` — no `omg::types::map`/`bounded_map` and none of the four traits.

## 7.14.3.2 Bitsets

**Status:** `partial` — bitsets are emitted as a struct with separate integer members, packed in the codec, not as C++ bit-fields; base bit-fields are folded in flat, not through public inheritance. The spec requires bit-fields as the only members.

## 7.14.3.3 Bitmask Type

**Status:** `partial` — a bitmask is emitted as an integer alias (uint8/16/32/64) plus `inline constexpr` bit constants, not as a `struct` with an unscoped `_flags` enum, a private `_value`, constructors, `!=`/`&=`/`^=` operators and a call operator. The `bit_bound`/`underlying_type` traits are missing.

## 7.14.4 8-bit Integer Types (Tab.7.13)

**Status:** `partial` — `octet`/`uint8` fall onto the same `std::uint8_t` (tag test). `int8 -> std::int8_t` has no assertion of its own.

## 7.14.5 Explicitly-Named Integer Types (Tab.7.14)

**Status:** `partial` — the explicit widths are mapped in `cpp_primitive`, but no assertion names `int16`/`uint16`/`int32`/`uint32`/`int64`/`uint64` individually.

## 7.17.1 General Purpose: @optional

**Status:** `open` — no mapping writes `std::optional<T>`: the default mapping (`psm`) writes `dds::core::optional<T>` (DDS-PSM-Cxx), the option `native` a pointer `T *` (DDS-XTypes 1.3 §7.5.1.2.4.2), the option `classic` `zerodds::classic::Optional<T>`. The form of IDL4 to C++ 1.0 §7.17.1 is missing as a named option. Evidence of the forms that exist: `crates/lang-rules/src/adapter/cpp_psm.rs` (`dds::core::optional<T>`), `crates/lang-rules/src/adapter/cpp.rs` (`T *`), `crates/lang-rules/src/adapter/cpp_classic.rs` (`zerodds::classic::Optional<T>`); tests `crates/lang-rules/src/adapter/cpp.rs::tests::an_optional_member_is_a_plain_pointer_and_not_a_second_field`, `crates/cpp/tests/generated_psm_roundtrip.cpp`.

## 7.17.1 General Purpose: @value, @position, @id, @autoid, @extensibility

**Status:** `partial` — `@value` reaches the enumerator value (the adapter writes every value out) but is not asserted directly; `@position` hangs on the bitmask, which is itself partial (§7.14.3.3); `@id`, `@autoid`, `@extensibility`, `@final`, `@mutable` and `@appendable` are, as the spec intends, not carried into the C++.

## 7.17.2 Data Modeling: @key, @must_understand, @default_literal

**Status:** `partial` — `@key` and `@must_understand` have no impact, as the spec says. `@default_literal` is not evaluated: the member default takes the **first** enumerator, not the one marked `@default_literal`.

## 7.17.3 Units and Ranges: @default, @range, @min, @max, @unit

**Status:** `open` — no `omg::types::ranged<T,min,max>`, no setters (the data members are public fields) and therefore no `std::out_of_range` check for `@range`/`@min`/`@max`. `@default` is evaluated in the codec defaulter (`crates/lang-rules/src/default_cpp.rs`), but not as the C++ member initialiser of the generated struct.

## 7.17.4 Data Implementation: @bit_bound

**Status:** `partial` — for enums the underlying type is asserted; for bitmasks the adapter follows the same width rule, but the bitmask mapping is itself partial (§7.14.3.3).

## 7.17.4 Data Implementation: @external

**Status:** `partial` — `@external T` is held as `std::shared_ptr<T>` (asserted). The required deep copy in the copy constructor is missing: the compiler-generated copy constructor copies the `shared_ptr` shallowly, so the object is shared.

## 7.17.5 Code Generation: @verbatim

**Status:** `partial` — all six placements (BEGIN_FILE, BEFORE/BEGIN/END/AFTER_DECLARATION, END_FILE) and the languages `c++`, `cpp`, `cxx` as well as `*` are live (asserted). `cc` — explicitly named in Tab.7.19 — is missing from `verbatim::aliases::CPP` (`&["c++", "cpp", "cxx"]`).

## 7.17.6 Interfaces: @service, @oneway, @ami

**Status:** `partial` — `@oneway` (no reply topic, `future<void>` async) and `@service` (service name) are handled through the DDS-RPC binding; `@ami` has no path of its own. Tab.7.20 explicitly calls the impact platform-specific.

## 8.1.1 CLASS_WITH_PUBLIC_ACCESSORS_AND_MODIFIERS

**Status:** `open` — no path emits the annotated struct as a class with private members, accessors/modifiers and an initialising constructor. `@cpp_mapping` is not read by `crates/lang-rules/src/adapter/cpp.rs`.

## A.1 CORBA-Specific Mappings

**Status:** `open` — no `CORBA::traits<>`/`CORBA::servant_traits<>` in the C++ column and no `omg::types`. `crates/corba-codegen/src/traits.rs` is a Rust CORBA generator, not this C++ binding.
